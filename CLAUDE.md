# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Infrastructure-as-config for the Stoganet home server. **No application code, no build system, no test suite** — just shell scripts, a Docker Compose file, a systemd unit, and JSON config snippets applied to running containers. Sister repo `Stoganet/stogad` holds the native daemon (Rust).

Two top-level deliverables:

- `compose/` — Docker Compose stack (Jellyfin, *arr stack, Gluetun+qBittorrent, Jellyseerr, Portainer) plus `setup.sh` (host bootstrap) and `configure-arr.sh` (idempotent post-deploy config of Sonarr/Radarr/qBittorrent via their REST APIs using JSON in `compose/arrconfig/`).
- `backup/` — LUKS-encrypted USB backup driven by a systemd timer. `setup.sh` is one-time drive init (LUKS2 + ext4 + keyfile); `backup.sh` runs daily, opens LUKS, and rclones Docker volumes (read from `/var/lib/docker/volumes/${COMPOSE_PROJECT}_*_config/_data`).
- `bin/` — host-side deploy/rollback/diagnostics scripts invoked by `.github/workflows/deploy.yml` over SSH. `deploy.sh` is idempotent (checkout SHA + `compose pull` + `up -d` + `./configure-arr.sh`); `rollback.sh` skips pull and configure-arr; `diagnostics.sh` is read-only.

## Architecture invariants

These cross-file constraints matter when editing:

- **Compose project name is `services`** (set by `name: services` in `compose/docker-compose.yml`). `backup/backup.sh` defaults `COMPOSE_PROJECT=services` and reads volumes at `${DOCKER_VOLUME_PATH}/${COMPOSE_PROJECT}_<volume>_config/_data`. Renaming the project breaks backups silently.
- **No WAN exposure.** Every service binds its host port to `${NETBIRD_IP}` only (the NetBird mesh interface), never `0.0.0.0`. No port forwarding, no reverse proxy on this box. Jellyfin, Jellyseerr, and api-proxy are additionally reachable from the public internet via NetBird Cloud's managed reverse proxy (configured in the NetBird dashboard, not in this repo) — everything else (portainer, the *arr stack, qbittorrent, uptime-kuma) is mesh-only, reached directly at `${NETBIRD_IP}:<port>`.
- **No TLS on this box.** Traefik was removed — NetBird Cloud terminates TLS for the three public services; mesh-only services are plain HTTP, protected by WireGuard encryption in transit rather than a second TLS layer. If a service needs a friendly hostname, point a DNS A record directly at `${NETBIRD_IP}`, don't reintroduce a reverse proxy for it.
- **qBittorrent has no network of its own.** It uses `network_mode: service:gluetun`. Its WebUI port and Traefik labels live on the `gluetun` service, not `qbittorrent`. If Gluetun's tunnel drops, all torrent egress dies (kill switch).
- **Media path is `/mnt/wd/media`** on the host, mounted into Jellyfin (`:ro`), qBittorrent, Sonarr, Radarr, Bazarr (all `:rw` at `/data`, except Jellyfin at `/media`). Keep this path consistent across services so the *arr stack's hardlinks work.
- **Secrets in `compose/.env`** (gitignored), generated by `compose/setup.sh`. Never commit `.env`. The setup script preserves existing values on re-run via `.env.bak`.
- **CI deploys run as `deploy@` over NetBird.** `.github/workflows/deploy.yml` joins the NetBird overlay using `NB_SETUP_KEY`, SSHes to `deploy@${HOME_OVERLAY_IP}` with `DEPLOY_SSH_KEY`, and invokes `/srv/stoganet/bin/deploy.sh`. Auto-triggers on push to main; `workflow_dispatch` allows manual re-runs of older SHAs. On healthcheck failure the workflow auto-rolls-back to the previously-deployed SHA via `bin/rollback.sh`. Don't introduce alternative deploy paths.

## Common operations

```bash
# Bring stack up / down (run from compose/)
docker compose up -d
docker compose logs -f <service>
docker compose pull && docker compose up -d   # update images

# Re-apply Sonarr/Radarr/qBittorrent settings (idempotent, safe to re-run)
./configure-arr.sh

# One-time host bootstrap (Docker, NetBird, UFW, ZRAM, GPU drivers, .env)
sudo ./setup.sh

# Backup ops (on host)
sudo systemctl start backup.service        # run backup now
sudo journalctl -u backup.service -f       # tail backup log
sudo systemctl list-timers backup.timer    # next scheduled run
```

There is no lint/test command — shell scripts use `set -euo pipefail`. If you need to validate, run `shellcheck` and `docker compose config` manually.

## Editing notes

- `compose/setup.sh` is **destructive on first run** (UFW reset, SSH config edit, swap removal). It guards with `ufw status | grep -qw active` and an `if [ -f /etc/ssh/sshd_config ]` check, but treat changes carefully. Re-runs preserve `.env`.
- `configure-arr.sh` auto-detects API keys by `docker exec`-ing into containers and grepping `/config/config.xml`. If you add a new arr service, follow the same pattern rather than requiring keys in `.env`.
- `backup/backup.sh` has a `cleanup` trap that unmounts and closes LUKS on any exit. Don't add `exit` paths that bypass it; let the trap fire.
- `bin/*.sh` is invoked by `deploy.yml` over SSH as the `deploy` user. Keep them POSIX-friendly and shellcheck-clean — CI enforces this. Changes to these scripts ship to prod on the next merge to main, same as any other change.

## Stoganet conventions

Skills in `.claude/skills/` enforce the org-wide workflow — invoke them via the Skill tool, don't reimplement:

- **committing** — Conventional Commits; `stogad` uses release-please so prefixes drive versioning. This repo doesn't release, but match the style.
- **creating-pull-requests** — PR title becomes the squash-commit; same conventional-commit rules.
- **creating-issues** — Shared label vocabulary and Summary/Context/Scope/Acceptance/Notes body across all Stoganet repos.
- **handoff** — Use before context compaction when there's uncommitted work worth preserving.
